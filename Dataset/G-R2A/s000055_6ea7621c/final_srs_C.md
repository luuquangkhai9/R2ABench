## 2. 总体描述

### 产品视角
该产品是一个由服务器支持的 Web 应用程序，具有：
- 一个 HTTP 路由器，在 `/` 提供主页
- 一个专用的 `search` 路由用于自动补全提示
- 面向公共资源的静态文件服务
- 针对本地数据测试的后端自动补全逻辑

来源：`E003`、`E004`、`E006`。

### 产品功能概述
- 接受用户文本输入以获取得主搜索建议。
- 在用户输入时返回诺贝尔奖得主建议。
- 提供应用程序主页。
- 提供公共静态资源。
- 基于存储的得主数据提供后端自动补全行为。

来源：`E001`、`E003`、`E004`、`E005`、`E006`。

## 4. 功能需求

| ID | 描述 | 触发器/输入 | 系统行为 | 输出 | 优先级 | 验证方式 | 来源证据 |
|---|---|---|---|---|---|---|---|
| FR-001 | 系统应允许用户在输入字段中输入文本以搜索诺贝尔奖得主。 | 用户在输入框中键入 | 系统接受输入的字符串作为搜索输入。 | 用于搜索处理的已捕获用户输入 | 高 | 演示、测试 | `E001`、`E002`、`E005` |
| FR-002 | 系统应针对输入的文本提供诺贝尔奖得主建议/列表结果。 | 用户在搜索时输入文本 | 系统返回合理的建议或与输入字符串匹配的诺贝尔奖得主列表。 | 搜索建议/列表结果 | 高 | 测试、演示 | `E001`、`E005`、`E006` |
| FR-003 | 当请求 URL 为 `/` 时，系统应提供应用程序主页。 | 向 `/` 发起 HTTP 请求 | 路由器将请求委派给主页处理，该处理读取并返回 `index.html`。 | 文件读取成功时返回带有 HTML 内容的 HTTP 200 响应 | 高 | 测试、检查 | `E003`、`E004` |
| FR-004 | 系统应将包含 `search` 的请求路由到自动补全提示处理。 | URL 包含 `search` 的 HTTP 请求 | 路由器将请求委派给自动补全处理程序。 | 由提示服务逻辑处理的搜索请求 | 高 | 测试、检查 | `E003` |
| FR-005 | 当请求不是 `/` 且不匹配 `search` 时，系统应提供所请求的公共静态资源。 | 针对公共资源的 HTTP 请求 | 路由器将请求委派给公共文件处理，该处理从 `public` 读取所请求的文件。 | 文件读取成功时返回包含所请求文件内容的 HTTP 响应 | 中 | 测试、检查 | `E003`、`E004` |

| FR-008 | 后端自动补全能力应基于从存储的得主数据派生出的数组值运行。 | 使用存储数据和搜索字符串进行后端自动补全调用 | 后端公开返回数组的值提取与自动补全操作。 | 数据提取和自动补全返回的数组结果 | 中 | 测试 | `E006` |
