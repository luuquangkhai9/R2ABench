## 2. 总体描述

### 产品视角
该系统是一个多层应用程序，其中每一层都托管在一个 Docker 容器中。前端使用 React 实现，后端使用 FastAPI，实现持久化歌曲/情绪存储的是 Elasticsearch，而 Kibana 用作检查已存储数据的更佳 UI。后端还依赖 Genius API 来搜索 Elasticsearch 中尚不存在的歌曲。[E003]

### 产品功能概述
- 提供一个可通过浏览器访问的前端以与应用程序交互。[E002][E003]
- 接收歌曲查询/分类请求。[E003]
- 当歌曲已存在时，从 Elasticsearch 中检索先前存储的歌曲情绪。[E003]
- 当歌曲尚未存储时，通过 Genius API 搜索歌曲。[E003]
- 将歌曲及其分类后的情绪存储到 Elasticsearch 中，以支持后续检索。[E003]
- 在项目数据范围内处理英文歌曲。[E005]

### 用户类别
- 终端用户：通过 Web 前端提交与歌曲相关的请求并接收情绪结果。[E002][E003]
- 开发者/运维人员：构建、运行、更新容器化组件，并使用 Kibana 检查已存储数据。[E001][E003][E004]

### 运行环境
- 用于访问前端的 Web 浏览器。[E002]
- 基于 Docker 的容器环境，其中每一层都托管在一个容器中。[E003]
- 支持 FastAPI 的后端运行时环境。[E003]
- Elasticsearch 和 Kibana 服务。[E003]

### 假设与依赖
- 对于 Elasticsearch 中尚不存在的歌曲，系统依赖 Genius API。[E003]
- 系统依赖 Elasticsearch 来检索已存储的歌曲和情绪。[E003]
- 项目数据范围仅限于英文歌曲。[E005]
- 根据项目故障排除指南，Windows 环境可能会因仓库位置而经历较慢启动。[E001]

## 3. 外部接口需求

### 用户接口
- 系统应提供一个可通过浏览器访问的 Web 前端。[E002][E003]
- Kibana 应作为与已存储 Elasticsearch 数据交互的 UI 可用。[E003]

### 软件/API 接口
- 前端应与 FastAPI 后端交互。[E003]
- 后端应与 Elasticsearch 对接以进行歌曲和情绪的存储/检索。[E003]
- 后端应与 Genius API 对接以搜索尚未存储的歌曲。[E003]

### 通信接口
- 浏览器到前端的通信应通过浏览器中的标准 Web 访问进行。[E002]
- 后端、Elasticsearch 和 Genius API 之间的服务到服务 API 通信是该架构所必需的。该协议细节是根据已识别的组件和 API 推断出的。[E003]

### 数据交换格式
仓库中有证据支持的数据对象包括：
- 歌曲名称 [E006]
- 歌曲链接表示（`SLink`）[E006]
- 歌词（`Lyric`）[E006]
- 语言 [E006]
- 艺术家名称 [E006]
- 艺术家流派 [E006]
- 艺术家歌曲数量 [E006]
- 歌曲情绪分类结果 [E003]
