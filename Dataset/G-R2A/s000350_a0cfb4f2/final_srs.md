# Software Requirements Specification

## 1. Introduction

### Purpose
This SRS defines the externally observable requirements for the `squatm3gator` API component evidenced in the repository snapshot at commit `d6e96d31b26d5dee3a4ddf2ae3cb516aa7da9ce5`. The document is limited to behavior directly supported by the repository evidence.

### Product scope
The evidenced product is a web API that:
- serves a web entry page,
- creates a user session,
- accepts domain-generation requests for squat/attack processing,
- dispatches jobs through Redis-backed worker communication,
- reports job progress or results over WebSocket,
- optionally integrates with GoDaddy domain availability endpoints.

### Intended audience
This document is intended for maintainers, integrators, testers, and operators of the API service and its dependent worker/integration components.

### References
- Repository: `david3107/squatm3gator`
- Snapshot: `d6e96d31b26d5dee3a4ddf2ae3cb516aa7da9ce5`
- Evidence IDs: `E001` to `E006`

## 2. Overall Description

### Product perspective
The product is a server-side API application with:
- an HTTP interface for page rendering, API requests, and error handling,
- a Redis-backed worker command/reporting flow,
- a WebSocket channel for asynchronous result delivery,
- an external dependency on GoDaddy availability APIs.

### Product functions summary
- Create a session and serve the main page.
- Start a background worker listener when the service begins handling requests.
- Accept attack-selection inputs and construct command options.
- Create and queue jobs tied to a session key / job UUID.
- Stream worker results back to the correct client session.
- Expose at least one GET resource for homoglyph-based domain generation.
- Return defined plain-text messages for common HTTP errors.

### User classes
- Web users requesting generated domains through the main page and API.
- Client applications consuming HTTP and WebSocket outputs.
- Background worker processes consuming queued jobs and publishing reports.
- Operators configuring Redis and GoDaddy credentials/endpoints.

### Operating environment
- Server runtime hosting an HTTP application and WebSocket support.
- Redis message queue at `redis://:waddup@redis:6379/`.
- External HTTP access to GoDaddy APIs using configured credentials.

### Assumptions and dependencies
- A worker consumer is available to listen for queued commands. (`E001`)
- Redis is reachable at the configured message queue URI. (`E001`)
- Session creation/checking is required before job submission and report correlation. (`E002`, `E006`)
- GoDaddy API credentials and endpoint configuration are available when that option is used. (`E005`)

## 3. External Interface Requirements

### User interfaces
- The system provides a web entry page rendered from `index.html` at the root path `/`. (`E003`)

### Software/API interfaces
- HTTP GET `/` returns the main page and creates a session. (`E003`)
- The system exposes at least one GET API resource for retrieving domains generated by the complete homoglyphs attack for a supplied domain value. (`E003`)
- The system accepts attack-related query inputs including attack codes, `godaddy`, and `output`. (`E002`, `E004`)
- The system emits asynchronous job messages/results through a WebSocket channel tied to the requesting session. (`E001`, `E006`)

### Communication interfaces
- Redis message queue interface: `redis://:waddup@redis:6379/`. (`E001`)
- GoDaddy API interface using HTTP requests with `Authorization: sso-key <key>:<secret>`. (`E005`)

### Data exchange formats
- Worker reporting message format: `WORKER_ID#JOB_UUID#{MESSAGE/RESULT}`. (`E001`, `E006`)
- Optional output format flag: `--output=json`. (`E002`, `E004`)

## 5. Non-Functional Requirements

| ID | Requirement | Quality attribute | Priority | Verification | Evidence | Confidence |
|---|---|---|---|---|---|---|
| NFR-001 | The system shall process domain-generation jobs asynchronously from HTTP request handling by using a background worker thread and a Redis-backed message queue. | Performance / responsiveness | High | Inspection | `E001`, `E002` | Explicit |
| NFR-002 | The system shall ensure result isolation between users by correlating reporting messages with the requesting session key and job ID before emitting them to clients. | Security / reliability | High | Test | `E001`, `E006` | Explicit |
| NFR-003 | When the JSON output option is requested, the system shall produce job options specifying `--output=json`. | Compatibility / data format | Medium | Test | `E002`, `E004` | Explicit |
| NFR-004 | The system should provide human-readable plain-text responses for HTTP 400, 404, 500, and query parsing failures. | Usability | Low | Test | `E002`, `E003`, `E004` | Inferred |

## 6. Data Requirements

| ID | Data item / entity | Requirement | Source evidence |
|---|---|---|---|
| DR-001 | Session key / job UUID | The system shall use a single identifier as both user session key and job ID for queued attacks and result correlation. | `E001`, `E002` |
| DR-002 | Worker report record | The system shall interpret reporting messages in the format `WORKER_ID#JOB_UUID#{MESSAGE/RESULT}`. | `E001`, `E006` |
| DR-003 | Attack selection input | The system shall accept attack-selection values from the set shown in evidence, including `Hf`, `Hc`, `-add`, `F`, and `R`, and map recognized values into command options. | `E002`, `E004` |
| DR-004 | Optional request flags | The system shall accept `godaddy` and `output` request flags, where `godaddy == 1` adds GoDaddy processing and `output == 1` requests JSON output. | `E002`, `E004` |
| DR-005 | GoDaddy credentials and endpoints | The system shall obtain GoDaddy integration data from configuration values for key, secret, API endpoints, API URL, and URL. | `E005` |
| DR-006 | Domain input | The system shall accept a domain value as input to the complete homoglyph retrieval resource and to GoDaddy availability checks. | `E003`, `E005` |

## 7. Constraints

| ID | Constraint | Source evidence |
|---|---|---|
| C-001 | The message queue integration is constrained to a Redis endpoint configured as `redis://:waddup@redis:6379/`. | `E001` |
| C-002 | GoDaddy integration is constrained to configured API endpoints and `sso-key` authorization using a configured key and secret. | `E005` |
| C-003 | The product behavior evidenced here depends on an external worker consumer that listens for queued commands. | `E001` |
