# 软件需求规格说明书

## 1. 引言

### 目的
本 SRS 定义了在提交 `d6e96d31b26d5dee3a4ddf2ae3cb516aa7da9ce5` 的仓库快照中有证据支持的 `squatm3gator` API 组件的对外可观察需求。本文档仅限于由仓库证据直接支持的行为。

### 产品范围
有证据支持的产品是一个 Web API，其功能包括：
- 提供一个 Web 入口页面，
- 创建用户会话，
- 接受用于 squat/attack 处理的域名生成请求，
- 通过 Redis 支持的 worker 通信分发作业，
- 通过 WebSocket 报告作业进度或结果，
- 可选地集成 GoDaddy 域名可用性端点。

### 目标受众
本文档面向 API 服务及其依赖的 worker/集成组件的维护者、集成人员、测试人员和运维人员。

### 参考资料
- 仓库：`david3107/squatm3gator`
- 快照：`d6e96d31b26d5dee3a4ddf2ae3cb516aa7da9ce5`
- 证据 ID：`E001` 到 `E006`

## 2. 总体描述

### 产品视角
该产品是一个服务端 API 应用，具有：
- 用于页面渲染、API 请求和错误处理的 HTTP 接口，
- Redis 支持的 worker 命令/报告流程，
- 用于异步结果交付的 WebSocket 通道，
- 对 GoDaddy 可用性 API 的外部依赖。

### 产品功能概述
- 创建会话并提供主页面。
- 在服务开始处理请求时启动后台 worker 监听器。
- 接受攻击选择输入并构造命令选项。
- 创建并排队与会话键 / 作业 UUID 绑定的作业。
- 将 worker 结果流式返回到正确的客户端会话。
- 至少公开一个用于基于 homoglyph 的域名生成的 GET 资源。
- 为常见 HTTP 错误返回定义好的纯文本消息。

### 用户类别
- 通过主页面和 API 请求生成域名的 Web 用户。
- 消费 HTTP 和 WebSocket 输出的客户端应用程序。
- 消费已排队作业并发布报告的后台 worker 进程。
- 配置 Redis 和 GoDaddy 凭据/端点的运维人员。

### 运行环境
- 承载 HTTP 应用和 WebSocket 支持的服务器运行时。
- 位于 `redis://:waddup@redis:6379/` 的 Redis 消息队列。
- 使用已配置凭据访问 GoDaddy API 的外部 HTTP 连接。

### 假设与依赖
- 有可用的 worker 消费者来监听已排队的命令。(`E001`)
- 可以通过已配置的消息队列 URI 访问 Redis。(`E001`)
- 在作业提交和报告关联之前，需要创建/检查会话。(`E002`, `E006`)
- 当使用该选项时，GoDaddy API 凭据和端点配置可用。(`E005`)

## 3. 外部接口需求

### 用户接口
- 系统在根路径 `/` 提供由 `index.html` 渲染的 Web 入口页面。(`E003`)

### 软件/API 接口
- HTTP GET `/` 返回主页面并创建会话。(`E003`)
- 系统至少公开一个 GET API 资源，用于检索针对给定域名值由完整 homoglyphs 攻击生成的域名。(`E003`)
- 系统接受与攻击相关的查询输入，包括攻击代码、`godaddy` 和 `output`。(`E002`, `E004`)
- 系统通过与请求会话绑定的 WebSocket 通道发出异步作业消息/结果。(`E001`, `E006`)

### 通信接口
- Redis 消息队列接口：`redis://:waddup@redis:6379/`。(`E001`)
- GoDaddy API 接口，使用带有 `Authorization: sso-key <key>:<secret>` 的 HTTP 请求。(`E005`)

### 数据交换格式
- Worker 报告消息格式：`WORKER_ID#JOB_UUID#{MESSAGE/RESULT}`。(`E001`, `E006`)
- 可选输出格式标志：`--output=json`。(`E002`, `E004`)
