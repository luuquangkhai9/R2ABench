# 软件需求规格说明书

## 1. 引言

### 目的
本 SRS 基于引用的仓库快照中 Soundzone 的仓库证据定义其有据可依的需求，并且仅使用与提交 `08662fb0cac176552459f4091db62bf7a90e54f8` 关联的仓库证据。

### 产品范围
Soundzone 是一个基于 SoundCloud 的 Web 应用程序，用户可以上传和播放声音，关注其他用户以播放其声音，并通过点击波形来拖动播放进度。该应用程序使用 React/Redux 前端、Node/Express 后端、PostgreSQL，以及用于音频和图像存储的 Cloudinary。来源：`E005`、`E006`。

### 目标读者
本文档面向维护者、审查者、测试人员以及评估仓库所支持行为和集成边界的利益相关者。

## 2. 总体描述

### 产品视角
Soundzone 是一个基于 Web 的音频共享和播放系统。大多数应用程序逻辑发生在前端，其中 Redux actions 会向后端和 Cloudinary 发起 fetch 调用。来源：`E005`。

### 产品功能概述
- 上传声音。来源：`E005`
- 播放声音。来源：`E005`
- 关注其他用户以访问并播放其声音。来源：`E005`
- 通过点击波形拖动声音播放进度。来源：`E005`
- 保持音频播放不中断，并在页面切换时保持播放状态。来源：`E001`、`E003`
- 在表单交互期间验证表单并提供错误处理。来源：`E002`、`E004`

### 用户类别
| 用户类别 | 描述 | 来源 |
|---|---|---|
| 终端用户 | 上传声音、播放声音、关注其他用户并与波形播放控件交互的用户 | `E005` |

### 运行环境
| 方面 | 要求 | 来源 |
|---|---|---|
| 客户端环境 | 产品应作为 Web 应用程序运行，前端逻辑使用 React 和 Redux 实现 | `E005` |
| 服务器环境 | 产品应使用 Node 和 Express 后端 | `E005` |
| 数据平台 | 产品应使用 PostgreSQL 存储应用程序数据，并使用 Cloudinary 存储音频和图像资源 | `E005`、`E006` |

### 假设与依赖
| 项目 | 描述 | 证据类型 | 来源 |
|---|---|---|---|
| Cloudinary 依赖 | 音频文件和图像依赖 Cloudinary REST API 存储，其 URL 引用存储在 PostgreSQL 中 | explicit | `E002`、`E004`、`E006` |
| 前端状态依赖 | 播放持久性依赖基于 Redux 的应用程序状态管理 | explicit | `E001`、`E003` |
| 后端/API 依赖 | 前端 actions 依赖对后端和 Cloudinary 的 fetch 调用 | explicit | `E005` |

## 4. 功能需求

| ID | 描述 | 触发器/输入 | 系统行为 | 输出 | 优先级 | 验证方式 | 来源证据 |
|---|---|---|---|---|---|---|---|
| FR-001 | 系统应允许用户上传声音。 | 用户通过 Web 应用程序提交声音上传。 | 系统接受上传请求，并使该声音在应用程序工作流中可用。 | 上传的声音可供后续在应用程序中播放/使用。 | 高 | 演示 | `E005` |
| FR-002 | 系统应允许用户播放声音。 | 用户选择一个声音进行播放。 | 系统开始播放所选声音的音频。 | 所选声音的可听播放。 | 高 | 演示 | `E005` |
| FR-003 | 系统应允许用户关注其他用户以播放其声音。 | 用户关注另一个用户。 | 系统记录用户播放该其他用户声音所需的基于关注的访问关系。 | 被关注用户的声音在应用程序上下文中可供播放。 | 高 | 测试 | `E005` |
| FR-004 | 系统应允许用户通过点击波形来拖动声音播放进度。 | 用户点击波形上的某个位置。 | 系统将播放更新到声音中的所选位置。 | 播放从点击的波形位置继续。 | 高 | 演示 | `E005` |
| FR-005 | 当播放新的声音时，系统应中断其他声音的播放。 | 当一个声音正在播放时，用户开始播放另一个不同的声音。 | 系统停止或中断先前播放的声音，并将当前声音管理为活动播放项。 | 只有新选择的声音继续作为活动播放。 | 高 | 测试 | `E001`、`E003` |
| FR-006 | 系统应在页面切换时保持音频播放。 | 当一个声音正在播放时，用户导航到另一个页面。 | 系统在页面切换后保持当前正在播放的音频状态。 | 音频播放持续，不会因导航而被重置。 | 高 | 测试 | `E001`、`E003` |
| FR-007 | 当组件发生变化时，系统应提供不中断的播放。 | 在活动播放期间发生组件或页面变化。 | 系统使播放独立于视图组件进行管理，从而使播放不会因可视导航变化而中断。 | 跨组件切换的连续播放体验。 | 中 | 测试 | `E001`、`E003` |
| FR-008 | 系统应在表单交互期间验证表单输入并提供错误处理。 | 用户输入或提交表单数据。 | 系统验证输入，并通过表单流程呈现验证或错误状态。 | 用户可见的验证反馈和错误处理。 | 中 | 测试 | `E002`、`E004` |
| FR-009 | 系统应将上传的音频文件和图像存储在 Cloudinary 中，并将其 URL 引用存储在 PostgreSQL 中。 | 用户上传音频文件或图像。 | 系统将二进制资源存储在 Cloudinary 中，并将相应的 URL 引用写入 PostgreSQL。 | 资源持久化到 Cloudinary 中，URL 引用持久化到 PostgreSQL 中。 | 高 | 检查 | `E002`、`E004`、`E006` |

## 5. 非功能需求

| ID | 质量属性 | 要求 | 优先级 | 验证方式 | 证据类型 | 来源证据 |
|---|---|---|---|---|---|---|
| NFR-001 | 可靠性 | 系统应在活动音频播放期间跨页面切换保持播放连续性。 | 高 | 测试 | explicit | `E001`、`E003` |
| NFR-002 | 播放体验可用性 | 当播放新的声音时，系统应通过保持一个受管理的当前声音并中断其他声音来避免同时发生冲突的播放。 | 高 | 测试 | explicit | `E001`、`E003` |
| NFR-003 | 存储效率 | 系统应将大型媒体资源存储在 Cloudinary 中而不是 PostgreSQL 中，并且仅在 PostgreSQL 中存储 URL 引用。 | 高 | 检查 | explicit | `E002`、`E004`、`E006` |
| NFR-004 | 可扩展性 | 使用 Cloudinary 存储音频和图像应解决与直接在 PostgreSQL 中存储媒体相关的应用程序扩展问题。 | 中 | 分析 | explicit | `E002`、`E004`、`E006` |
| NFR-005 | 易用性 | 面向用户的表单应在数据输入和提交期间提供验证和错误处理。 | 中 | 测试 | explicit | `E002`、`E004` |

| 输出 | 系统应在 PostgreSQL 中持久化已上传音频和图像资源的 URL 引用 | `E002`、`E004`、`E006` |
