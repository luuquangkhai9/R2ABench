# 软件需求规格说明书

## 1. 引言

### 目的
本 SRS 定义了针对 `earth-defender` 产品在提交 `5d4d8f0832fc74882a701d6a0dedee23fd494648` 时的、基于证据的需求，重点关注其分布式客户端/服务器多人游戏功能和接口的可观察行为。

### 产品范围
`Earth Defender` 是一个使用 Erlang/OTP 和 Three.js 构建的分布式软实时 3D 游戏，支持单人和多人游戏。现有证据主要描述了基于房间的多人游戏、客户端/服务器启动，以及浏览器客户端与游戏服务器之间基于 WebSocket 的运行时接口。[E001][E002]

## 2. 总体描述

### 产品视角
该产品是一个具有独立客户端和服务器组件的分布式游戏。在多人模式下，通信通过浏览器客户端与服务器之间基于 HTTP 的 WebSocket 实现。浏览器客户端发起服务器连接；该设计不支持浏览器到浏览器的点对点连接。[E001][E002]

### 产品功能概述
证据支持以下产品功能：
- 启动并运行独立的客户端和服务器组件 [E001]
- 支持多人房间工作流，包括创建房间和加入房间 [E001]
- 通过 WebSocket 交换游戏和控制消息 [E002][E003][E004]
- 使用 `ping`/`pong` 消息维持连接存活性 [E003][E006]
- 在连接关闭后重新连接，并在 `game_reconnect` 时恢复游戏状态 [E004]
- 向客户端提供服务器列表信息和重定向行为 [E006]
- 为容错目的支持从属/副本服务器部署 [E002]

### 用户类别
- 玩家：使用浏览器客户端以单人或多人模式进行游戏 [E001]
- 房主/创建房间的玩家：发起一个新的多人房间 [E001]
- 加入房间的房间参与者：加入一个现有的多人房间 [E001]
- 服务器运维人员：构建、启动并配置游戏服务器及可选的从属/副本 [E001][E002]

### 运行环境
- 使用 Three.js 的基于浏览器的客户端环境 [E001]
- 使用 Erlang/OTP 的服务器环境 [E001]
- 支持浏览器客户端与服务器之间 HTTP 和 WebSocket 连接的网络环境 [E002]

### 假设和依赖
- 浏览器客户端可以发起但不能接受 WebSocket 连接。[E002]
- 多人游戏运行依赖于位于已配置地址和端口上的可用服务器。[E002]
- 容错副本行为依赖于单独的从属/副本部署。[E002]

## 3. 外部接口需求

### 用户界面
产品提供一个 3D 游戏客户端，并支持用于创建房间和加入房间的多人用户流程。现有证据不支持更详细的屏幕布局信息。[E001]

### 软件/API 接口
| 接口 | 需求 |
|---|---|
| 客户端-服务器会话 | 浏览器客户端应使用基于 HTTP 的 WebSocket 与游戏服务器通信。[E002] |
| 出站消息格式 | 客户端应将出站消息编码为形如 `[event, data]` 的 JSON 数组。[E003] |
| 入站消息格式 | 客户端应将入站 WebSocket 消息解析为 JSON 数组，其中元素 `0` 是动作，元素 `1` 是可选数据。[E004][E005] |
| 运行时动作 | 客户端中有证据表明支持的入站动作包括 `game_reconnect`、`room_players_number`、`servers_list`、`servers_list_redirect`、`server_error` 和 `pong`。[E004][E006] |

### 通信接口
| 接口方面 | 需求 |
|---|---|
| 传输 | 通信应使用运行在 HTTP 之上的 WebSocket。[E002] |
| 方向性 | 浏览器客户端应发起到服务器的连接；文档化架构不支持客户端到客户端的 P2P 通信。[E002] |
| 存活性 | 客户端在连接期间应定期发送 `ping` 消息并处理 `pong` 响应。[E003][E006] |

### 数据交换格式
| 数据 | 格式 | 证据 |
|---|---|---|
| 客户端出站消息 | JSON 数组 `[event, data]` | [E003] |
| 服务器入站消息 | JSON 数组 `[action, data?]` | [E004][E005] |
| 重连上下文 | 在重连流程中包含房间 ID、玩家 ID 和索引的数组 | [E004][E005] |

## 6. 数据需求

## 7. 约束

| ID | 约束 | 来源证据 |
|---|---|---|
| C-001 | 产品被约束为分布式客户端/服务器架构，并具有独立的客户端和服务器设置/启动过程。 | [E001] |
| C-002 | 多人浏览器通信被约束为基于 HTTP 的 WebSocket。 | [E002] |
| C-003 | 浏览器客户端不能接受入站 WebSocket 连接；因此文档化架构不支持客户端到客户端的 P2P 通信。 | [E002] |
| C-004 | 有证据表明所使用的实现技术为服务器端的 Erlang/OTP 和客户端的 Three.js。 | [E001] |
