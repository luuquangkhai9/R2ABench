# 软件需求规格说明书

## 1. 引言

### 目的
本 SRS 定义了针对 `user-in-the-box` 仓库在提交 `5a4bb88b7ad8462173923808ab30c58224ef40d0` 时的、基于证据的需求。该规格说明涵盖了仓库中有证据支持的模拟器构建、集成和评估能力。

### 产品范围
`user-in-the-box` 提供了用于在 MuJoCo 中建模和模拟 HCI 交互任务的源代码。它支持具有生物力学驱动和感知能力的用户模型，在整体工作流中使用强化学习，并提供了一种模块化方式，将模拟器组装为实现 OpenAI Gym 接口的独立软件包。模拟器由 YAML 配置文件构建，这些文件用于选择和集成模型与任务。[E001, E003, E004]

### 目标读者
本文档面向：
- 扩展生物力学、感知或任务模块的开发人员
- 从配置构建模拟器的集成人员
- 评估已训练模拟器运行结果的用户

## 2. 总体描述

### 产品视角
该产品是一个用于 MuJoCo 中 HCI 交互任务的模拟器框架。它被设计为一个模块化组合系统，其中生物力学模型、感知模块和交互任务被组合成独立模拟器。生成的模拟器暴露 OpenAI Gym 接口。[E001, E003, E004]

### 产品功能概述
- 在 MuJoCo 中对 HCI 交互任务进行建模和模拟 [E001]
- 使用具备肌肉驱动生物力学模型和感知能力来表征用户 [E001]
- 支持模块化添加新的生物力学模型、感知模型和交互任务 [E001, E004]
- 从 YAML 配置文件构建模拟器 [E004]
- 将模拟器打包为可独立共享的单元 [E001]
- 支持从已存储的运行文件夹执行评估并生成评估输出 [E002]

### 用户类别
- 从 YAML 配置和组装模拟器的模拟器构建者 [E004]
- 创建新的感知模块及其他模型/任务扩展的模块开发者 [E001, E004]
- 运行已保存训练输出以进行评估的评估人员 [E002]

### 运行环境
- 基于 MuJoCo 的仿真环境 [E001, E003]
- 与 OpenAI Gym 兼容的模拟器接口 [E001, E003]
- 能够读取 YAML 配置文件并创建输出目录的文件系统环境 [E002, E004]

### 假设与依赖
- 模拟器构建依赖于定义所选集成模型的 YAML 配置文件。[E004]
- 模拟器依赖于构建期间的 MuJoCo XML 集成。[E004]
- 评估依赖于包含模拟器工件和检查点的运行文件夹。[E002]

## 3. 外部接口需求

### 用户界面
没有证据表明存在图形用户界面。有证据表明存在命令行评估工作流，其参数包括 `run_folder` 以及可选的动作日志输出命名。[E002]

### 软件/API 接口
- 模拟器应实现 OpenAI Gym 接口。[E001, E003]
- 在添加感知扩展时，此类扩展应符合仓库的感知模块结构和基类契约。[E004]

### 通信接口
没有证据表明存在网络或进程间通信接口。

### 数据交换格式
- YAML 应用于模拟器配置文件。[E004]
- MuJoCo XML 应用于构建期间的模拟器和生物力学模型集成。[E004]
