# 软件需求规格说明书

## 1. 引言

### 1.1 目的
本 SRS 规定了一个系统的由存储库支持的需求，该系统通过负载均衡、自动扩缩容的 GKE 部署，使用 WebSockets 将 Google Cloud Pub/Sub 主题消息分发给 Web 客户端。

### 1.2 产品范围
该产品提供基础设施和运行时行为，用于将来自一个 Pub/Sub 主题的消息镜像到通过单个 WebSocket 端点连接的客户端，而无需这些客户端使用 Pub/Sub API 或 SDK。它旨在运行于 Google Kubernetes Engine (GKE) 中、位于负载均衡器之后，并根据客户端连接数进行扩缩容。

### 1.3 预期受众
- 基于 GKE 的适配器的部署人员和运维人员
- 将 Web 客户端连接到镜像 Pub/Sub 主题数据的集成人员
- 执行部署和验收验证的审查人员

### 1.4 参考资料

- 存储库 URL：https://github.com/GoogleCloudPlatform/gke-pubsub-websocket-adapter

## 2. 总体描述

### 2.1 产品视角
该产品是一个 WebSocket 适配器和部署包，位于 Google Cloud Pub/Sub 主题与浏览器或其他 Web 客户端之间。它为负载均衡、自动扩缩容的 GKE 集群创建支持基础设施，以将主题消息镜像到已连接的客户端。Kubernetes Service 对外暴露该适配器。

### 2.2 产品功能概述
- 将 Pub/Sub 主题消息镜像到通过 WebSocket 连接的客户端
- 为一个 Pub/Sub 主题暴露单个客户端端点
- 在集群实例之间对客户端流量进行负载均衡
- 基于已连接客户端数量自动扩缩容
- 在每个 VM 仅使用一个订阅的同时复用大量客户端连接
- 向客户端提供最近 10 条主题消息的缓存

### 2.3 用户类别
- 具有 GCP 项目访问权限和所需权限的部署运维人员
- 通过 WebSockets 使用镜像主题消息的 Web 客户端

### 2.4 运行环境
- 已启用结算的 Google Cloud Platform 项目
- Google Kubernetes Engine 集群
- 类型为 `LoadBalancer` 的 Kubernetes Service
- 暴露端口 `8080` 的容器化运行时，Service 端口为 `80/TCP`

### 2.5 假设与依赖
- 目标 Pub/Sub 主题可由部署用户或服务账号读取。(`E002`)
- 部署需要创建 Pub/Sub 订阅的权限。(`E002`)
- 提供了一个主题标识符作为配置。(`E005`)
- 该解决方案依赖于 Google Cloud Pub/Sub、GKE、Kubernetes Service 网络以及 WebSocket 客户端连接能力。(`E002`, `E003`, `E004`)

## 3. 外部接口需求

### 3.1 用户接口
没有图形用户界面的证据。对外可见的面向用户接口是供 Web 客户端使用的 WebSocket 端点。(`E002`, `E004`)

### 3.2 软件/API 接口
| 接口 | 描述 | 来源 |
|---|---|---|
| Google Cloud Pub/Sub 主题 | 要镜像到客户端的消息来源 | `E002`, `E005` |
| Pub/Sub 订阅创建 | 用于消费主题数据所需的部署能力 | `E002` |
| Kubernetes ConfigMap | 通过键 `topic` 提供主题标识符 | `E005` |
| Kubernetes Service | 通过负载均衡服务暴露应用程序 | `E003` |

### 3.3 通信接口
| 接口 | 需求支持的细节 | 来源 |
|---|---|---|
| WebSocket 客户端连接 | 客户端通过映射到单个 Pub/Sub 主题的单一端点连接 | `E004` |
| Service 网络接口 | Kubernetes Service 应暴露 `port: 80`、`protocol: TCP`、`targetPort: 8080` | `E003` |

### 3.4 数据交换格式
| 数据项 | 格式/细节 | 来源 |
|---|---|---|
| 主题标识符 | 字符串，格式如示例所示：`projects/pubsub-public-data/topics/taxirides-realtime` | `E005` |
| 镜像主题消息 | Pub/Sub 主题消息被转发给 WebSocket 客户端；证据中未指定载荷格式 | `E002`, `E004` |
| 缓存消息集 | 向客户端提供最近发布的 10 条消息 | `E004`, `E006` |

## 6. 数据需求

### 6.1 数据实体或对象
| 数据实体 | 描述 | 来源 |
|---|---|---|
| Pub/Sub 主题 | 其消息被镜像到客户端的源流 | `E002`, `E005` |
| 主题标识符 | 作为 ConfigMap 键 `topic` 存储的已配置字符串 | `E005` |
| 主题消息 | 被转发给客户端并用于填充缓存的已发布消息 | `E002`, `E004`, `E006` |
| 缓存消息集 | 最近发布到该主题的 10 条消息 | `E004`, `E006` |

### 6.2 输入/输出数据
| 方向 | 数据 | 需求 |
|---|---|---|
| 输入 | 已配置的主题标识符 | 系统应接受已配置的主题值，作为要镜像的主题。(`E005`) |
| 输入 | 已发布的 Pub/Sub 消息 | 系统应消费来自已配置主题的消息以进行转发。(`E002`) |
| 输出 | 通过 WebSocket 传递的镜像消息 | 系统应将主题消息发送给已连接的 Web 客户端。(`E002`, `E004`) |
| 输出 | 缓存的近期消息 | 系统应向客户端提供最近 10 条消息。(`E004`, `E006`) |

### 6.3 存储、完整性、保留
| 需求 | 来源 |
|---|---|
| 系统应保留最近发布到该主题的 10 条消息的缓存，用于向客户端传递。 | `E004`, `E006` |

## 7. 约束

| ID | 约束 | 来源 |
|---|---|---|
| C-001 | 部署需要一个已启用结算的 GCP 项目。 | `E002` |
| C-002 | 部署需要对被镜像主题的读取访问权限；如果部署用户或服务账号可读取，该主题可以位于单独的项目中。 | `E002` |
| C-003 | 部署需要 Pub/Sub 订阅创建权限。 | `E002` |
