# 软件需求规格说明书

## 1. 引言

### 目的
本 SRS 定义了 `JSeats` 的有证据支持的需求。`JSeats` 是一个用于选举席位分配的 Java 库和命令行工具，仅基于提交 `3e4c0686a09ed12b6024d264168e317eebe678a4` 的仓库证据。

### 产品范围
`JSeats` 通过 Java API 和命令行启动器提供选举席位分配算法。已文档化的范围包括多数制、排序法、等比例法、最大余数法和最高平均数法等方法族，以及诸如 D'Hondt、Sainte-Lague (Webster)、Hare、Droop、Imperiali 和 Danish 等具名变体。[E004]

### 目标读者
目标读者包括：
- 通过 Java API 将席位分配集成到软件中的 Java 开发人员。[E004, E002]
- 在终端中运行席位分配的命令行用户。[E004]

## 2. 总体描述

### 产品视角
`JSeats` 是一个用 Java 实现的选举席位分配组件。它暴露了一个程序化处理接口，该接口接收计票结果和方法属性并返回结果，同时还提供了一个命令行启动器。[E004, E002]

### 产品功能概述
该产品支持：
- 使用常见选举方法进行席位分配。[E004]
- 通过 Java API 将计票结果处理为结果。[E001, E002]
- 通过 `Properties` 进行方法特定参数化。[E002, E005]
- 通过单独的装饰器接口进行结果修饰。[E003]
- 由 `Tally.fromXML()` 表明的基于 XML 的计票结果加载。[E001]

### 用户类别
- 使用 Java API 的应用开发人员。[E004, E002]
- 使用命令行启动器的操作人员或分析人员。[E004]

### 运行环境
- Java 运行时环境。[E004]
- 用于启动器使用的命令行 shell 环境。[E004]

### 假设与依赖
- 席位分配处理依赖于调用方提供的计票结果和方法属性。[E002]
- 某些方法依赖于从计票结果派生的值，例如潜在票数和候选人数。[E005, E006]

## 3. 外部接口需求

### 用户接口
| 接口 | 需求 |
|---|---|
| 命令行 | 系统应提供一个命令行启动器来调用席位分配功能。[E004] |

### 软件/API 接口
| 接口 | 需求 |
|---|---|
| Java 处理 API | 系统应提供一个用于席位分配处理的 Java API。该处理接口接收不可变的计票结果和方法属性，并返回结果或引发席位分配异常。[E004, E002] |
| 结果修饰 API | 系统应提供一个接口，用于将结果后处理为修饰后的结果。[E003] |

### 通信接口
在所提供材料中，没有网络或进程间通信接口的证据。

### 数据交换格式
| 格式 | 用途 |
|---|---|
| 内存中的 Java 对象 | `Tally`、候选人、结果和属性通过 Java API 进行交换。[E001, E002] |
| XML | 可使用 `Tally.fromXML()` 从 XML 加载计票结果。[E001] |

| ID | 数据项 | 需求 | 来源证据 |

## 7. 约束

| ID | 约束 | 来源证据 |
|---|---|---|
| C-001 | 产品受限于 Java 实现。 | [E004] |
| C-002 | 公共处理契约受限于以不可变计票结果和 Java `Properties` 作为输入，并以 `Result` 或 `SeatAllocationException` 作为输出。 | [E002] |
