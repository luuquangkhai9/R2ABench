# 软件需求规格说明书

## 1. 引言

### 目的
本 SRS 定义了针对提交 `9e995377e5dd8669c96a13d79a196737a41cef2b` 时 `lowes/auditor` 组件的、基于证据支撑的需求。文档范围限定为客户端审计能力，即比较对象状态并发布审计事件。来源仅限于仓库证据包。`E001`, `E002`, `E003`

### 产品范围
该产品提供一个面向应用的审计 API，接收旧对象状态、新对象状态以及可选的事件配置，然后生成一个描述已检测变更的 `AuditEvent`。现有证据表明其支持配置应用名称、事件源、事件子类型、元数据和元素过滤器，并支持发布可被作为 `AuditEvent` 对象消费的序列化审计事件。`E001`, `E002`, `E003`

### 预期读者
本文档适用于：
- 将 auditor 客户端 API 集成到其服务中的应用开发人员。`E003`
- 验证已发出审计事件的测试与 QA 工程师。`E001`, `E002`
- 事件发布与过滤集成的维护人员。`E003`

### 参考资料
- 仓库：`https://github.com/lowes/auditor`
- 快照：`https://github.com/lowes/auditor/tree/9e995377e5dd8669c96a13d79a196737a41cef2b`
- 主要证据：`E001` 到 `E006`

## 2. 总体描述

### 产品视角
`lowes/auditor` 是更大应用架构中的一个客户端库组件。它依赖于可插拔的基础设施接口，包括 `EventPublisher`、`LogProvider` 和 `AuditEventElementFilter`。`E003`

### 产品功能概述
支持的产品功能包括：
- 接收旧对象状态和新对象状态以进行审计比较。`E001`, `E002`
- 生成一个 `AuditEvent`，标识已更新元素，包括先前值、更新值以及元素元数据。`E002`
- 应用调用方提供的事件配置，例如应用名称、事件源、事件子类型、元数据和元素过滤器。`E001`, `E002`
- 通过事件发布接口发布生成的审计事件。`E003`

### 用户类别
- 调用审计 API 的集成应用开发人员。`E001`, `E002`, `E003`
- 提供事件发布和日志实现的基础设施集成人员。`E003`

### 运行环境
该组件实现为 Kotlin 库，并在基于 Kotlin 的客户端和示例模块中得到证实。这意味着其集成环境基于 JVM。`E003`, `E005`, `E006`  
证据类型：JVM 环境为推断得出。

### 假设与依赖
- 该组件需要一个事件发布实现来投递审计事件。`E003`
- 该组件使用过滤支持来限制哪些元素会被审计。`E001`, `E003`
- 消费系统应将发出的负载反序列化为 `AuditEvent` 对象。`E001`, `E002`

## 3. 外部接口需求

### 用户接口
所提供材料中没有证实任何面向终端用户的图形界面或命令行界面。

### 软件/API 接口
| 接口 | 需求 |
|---|---|
| 审计 API | 系统应暴露一个 API，调用方可通过其提供 `oldObject`、`newObject` 以及可选的 `AuditorEventConfig` 以启动审计。`E001`, `E002`, `E003` |
| 配置输入 | API 应接受 `applicationName`、`eventSource`、`eventSubType`、`metadata` 和元素过滤器的配置值。`E001`, `E002` |
| 发布器集成 | 系统应与 `EventPublisher` 抽象集成以进行事件投递。`E003` |

### 通信接口
| 接口 | 需求 |
|---|---|
| 事件发布 | 系统应将审计结果发布为序列化事件消息，能够被消费并反序列化为 `AuditEvent`。`E001`, `E002`, `E003` |

### 数据交换格式
| 格式 | 证据 |
|---|---|
| `AuditEvent` 序列化负载 | 功能测试会将消费到的消息值反序列化为 `AuditEvent`。`E001`, `E002` |
| 事件元素负载 | 事件元素包括 `name`、`updatedValue`、`previousValue` 和 `metadata.fqdn`。`E002` |
| 领域对象输入 | 示例领域对象包括标量、map、list、嵌套对象和 UUID 字段。`E005`, `E006` |

## 6. 数据需求

| ID | 数据实体 / 对象 | 需求 | 来源证据 |
|---|---|---|---|
| DR-001 | `AuditEvent` | 审计输出应可表示为一个 `AuditEvent` 对象，以供下游反序列化器消费。 | `E001`, `E002` |
| DR-002 | 事件元素 | `AuditEvent` 中的每个已更新元素应支持 `name`、`updatedValue`、`previousValue` 和 `metadata.fqdn`。 | `E002` |
| DR-003 | `AuditorEventConfig` | 审计请求配置应支持 `applicationName`、`eventSource`、`eventSubType`、`metadata` 以及 `filters.element` 选项，包括 `enabled`、`types` 和 `includes`。 | `E001`, `E002` |
| DR-004 | 领域对象输入 | 如示例 `Item` 模型所示，系统输入领域对象可包含 UUID、可空与非空标量字段、maps、lists 和嵌套对象。 | `E005`, `E006` |
