# 软件需求规格说明书（SRS）

## 1. 引言

### 1.1 目的
本 SRS 定义了基于证据支持的 PlugIt 需求，这些需求以仓库 `ebu/PlugIt` 在提交 `c2c0f6df09e43c1aa942716ebdf0afd99e262f67` 时的内容为代表。

### 1.2 产品范围
PlugIt 是一个框架，旨在提升需要用户界面的微服务的可移植性与集成能力。其被描述为使开发者能够构建通用服务，这些服务可通过单一体验和用户界面集成到多个环境中，同时保持数据和流程隔离。它还包括服务配置、数据库支持的服务、API 访问以及邮件驱动处理工作流示例的支持材料。  
来源：[E004], [E002], [E001], [E003], [E005], [E006]

### 1.3 预期读者
- 创建新的基于 PlugIt 服务的服务开发者
- 将服务连接到 PlugIt Proxy API 的集成人员
- 配置数据库和特定环境设置的部署与运维人员
- 维护数据库支持或邮件集成的 PlugIt 服务的维护人员  
来源：[E002], [E001], [E003], [E005], [E006]

## 2. 总体描述

### 2.1 产品视角
PlugIt 被定位为一个框架，用于在统一的用户体验之后组合多个微服务，同时保留服务隔离。它还被描述为创建带有子模块、数据库支持和部署脚本的新服务的基础。  
来源：[E004], [E002]

### 2.2 产品功能概要
- 将多个微服务集成到单一用户体验中
- 将服务连接到 PlugIt Proxy API 端点
- 支持特定环境的服务配置
- 支持带有版本化模式更新的数据库支持服务
- 提供入站邮件的验证与路由处理示例  
来源：[E004], [E002], [E001], [E003], [E005], [E006]

### 2.3 用户类别
| 用户类别 | 描述 | 来源 |
|---|---|---|
| 服务开发者 | 创建新的 PlugIt 项目，配置设置，定义模型，并管理模式变更 | [E002], [E001] |
| 集成人员 | 将服务连接到 PlugIt Proxy API 和部署环境 | [E002], [E003], [E004] |
| 运维人员/管理员 | 配置数据库实例并管理特定部署的设置 | [E001], [E002] |
| 邮件工作流维护人员 | 运行入站邮件处理与路由行为 | [E005], [E006] |

### 2.4 运行环境
- 可访问 PlugIt Proxy API URL 的部署环境
- 已配置的数据库，示例包括 MySQL 和 SQLite
- 用于服务专属设置和本地/私有设置的配置文件
- 对于邮件处理场景，可访问入站电子邮件消息  
来源：[E002], [E001], [E005], [E006]

### 2.5 假设与依赖
- PlugIt Proxy API 端点可用，并通过 `API_URL` 进行配置  
  来源：[E002]
- 数据库在使用框架之前已在框架外部被选定、创建并配置  
  来源：[E001]
- 私有设置保存在一个排除在源代码控制之外的本地配置文件中  
  来源：[E002]

## 3. 外部接口需求

### 3.1 用户界面
PlugIt 应支持通过单一体验和用户界面集成多个微服务。证据包中未定义具体的 UI 布局和交互模式。  
来源：[E004]

### 3.2 软件/API 接口
| 接口 | 需求摘要 | 来源 |
|---|---|---|
| PlugIt Proxy API | 服务应能够使用指向 PlugIt Proxy API 的 `API_URL` 进行配置 | [E002] |
| 编程式 API 访问 | 产品包括一个使用主 API 端点 URL 实例化的 API 访问设施 | [E003] |
| 数据库接口 | 服务可使用已配置的 SQLAlchemy 数据库 URL 和受版本管理的模式更新 | [E002], [E001] |
| 邮件回调接口 | 邮件处理将解码后的路由数据和提取出的文本载荷传递给 `newMail(data, payload)` | [E005] |

### 3.3 通信接口
| 接口 | 描述 | 来源 |
|---|---|---|
| Proxy API 端点 | 与 PlugIt Proxy API 的基于 URL 的通信 | [E002], [E003] |
| 邮件接收 | 对传入的电子邮件消息进行解析，并有条件地处理或丢弃 | [E005], [E006] |

### 3.4 数据交换格式
| 数据项 | 证据指示的格式 | 来源 |
|---|---|---|
| `API_URL` | 字符串 URL | [E002] |
| `SQLALCHEMY_URL` | 字符串连接 URL | [E002] |
| `PI_BASE_URL` | 字符串路径，示例 `'/'` | [E002] |
| `PI_ALLOWED_NETWORKS` | CIDR 格式网络字符串列表，示例 `['127.0.0.1/32']` | [E002] |
| 邮件令牌 | `hash:data`，然后解码为 `projectid, data` | [E006] |
| 邮件载荷 | 电子邮件消息的第一个文本部分 | [E005] |

## 4. 功能需求

| ID | 描述 | 触发器/输入 | 系统行为 | 输出 | 优先级 | 验证 | 来源证据 |
|---|---|---|---|---|---|---|---|
| FR-001 | 系统应支持通过项目配置文件和本地配置文件进行特定部署配置。 | 创建或部署 PlugIt 服务；`API_URL`、`SQLALCHEMY_URL`、`DEBUG`、`PI_BASE_URL`、`PI_ALLOWED_NETWORKS` 的配置值 | 系统应从配置文件中接受这些设置，并使用它们定义 API 端点、数据库连接、调试模式、基础 URL 和允许的网络。 | 适用于其目标环境的已配置服务实例 | 高 | 检查 | [E002] |
| FR-002 | 系统应支持带有版本管理模式升级的数据库支持服务。 | 服务模型发生变更并需要更新数据库模式 | 系统应使用由 Alembic 管理的升级文件来表示模式版本变更，并使协作者和生产部署能够执行数据库升级。 | 升级文件和可升级的数据库模式 | 中 | 演示 | [E001] |
| FR-003 | 系统应支持在保持数据和流程隔离的同时，将多个微服务组合到单一体验和用户界面中。 | 将一个或多个微服务集成到某个环境中 | 系统应允许在统一体验之下组合服务，而不合并它们的数据和流程边界。 | 集成后的微服务环境 | 高 | 演示 | [E004] |
| FR-004 | 系统应使用已配置的主端点 URL 提供对 PlugIt API 的编程式访问。 | 客户端提供主 API 端点 URL | 系统应创建一个绑定到该端点的 API 访问实例，以供后续 API 使用。 | 已初始化的 API 访问设施 | 中 | 演示 | [E003] |
| FR-005 | 系统应从入站电子邮件消息中提取第一个文本部分，并将其与解码后的路由数据一起提交给邮件处理器。 | 收到包含文本内容和可解码路由数据的入站电子邮件消息 | 系统应解码消息载荷，获取第一个文本部分，并调用 `newMail(data, payload)`。如果处理器报告成功，则已处理的消息应被确认并删除。 | 处理器调用结果；成功的消息从邮箱中移除 | 中 | 测试 | [E005] |
| FR-006 | 系统应在邮件处理之前验证入站邮件路由令牌并抑制自动回复消息。 | 收到入站电子邮件消息 | 系统应将期望的哈希与接收到的哈希进行比较，拒绝哈希不符合预期的消息，识别自动回复指示，并丢弃自动回复消息而不是处理它们。 | 无效或自动回复消息不会被处理 | 高 | 测试 | [E006] |

## 5. 非功能需求

| ID | 质量属性 | 需求 | 优先级 | 验证 | 证据类型 | 来源证据 |
|---|---|---|---|---|---|---|
| NFR-001 | 可移植性 | 产品应通过将特定环境的设置外置到配置文件中而非硬编码，从而支持在多个环境中部署服务。 | 高 | 检查 | 明确 | [E004], [E002] |
| NFR-002 | 可维护性 | 数据库模式演进应通过 Alembic 版本文件进行管理，以便在开发和生产环境中一致地应用模式更新。 | 中 | 检查 | 明确 | [E001] |
| NFR-003 | 机密性 | 私有部署设置应保存在排除于源代码控制之外的本地配置文件中，以减少私有设置被意外公开的风险。 | 高 | 检查 | 明确 | [E002] |
| NFR-004 | 可靠性 | 邮件处理应避免对自动生成的回复和具有无效路由哈希的消息采取动作。 | 高 | 测试 | 明确 | [E006] |

## 6. 数据需求

| ID | 数据实体/对象 | 需求 | 来源证据 |
|---|---|---|---|
| DR-001 | 服务配置 | 系统应使用 `API_URL`、`SQLALCHEMY_URL`、`DEBUG`、`PI_BASE_URL` 和 `PI_ALLOWED_NETWORKS` 的配置数据。 | [E002] |
| DR-002 | 数据库模式版本数据 | 当模型发生变化时，系统应通过 Alembic 生成的升级文件维护带版本的数据库升级信息。 | [E001] |
| DR-003 | 邮件路由令牌 | 系统应处理格式为 `hash:data` 的邮件路由令牌，并进一步将 `data` 解码为 `projectid` 和剩余数据。 | [E006] |
| DR-004 | 邮件载荷 | 系统应提取入站电子邮件的第一个文本部分，以供下游处理。 | [E005] |
| DR-005 | 邮件完整性检查数据 | 系统应使用 `sha512(data + secret)` 推导期望哈希，并在处理前将该摘要的子串与接收到的哈希进行比较。 | [E006] |

## 7. 约束

| ID | 约束 | 来源证据 |
|---|---|---|
| C-001 | 在配置之前必须在外部选择并配置数据库技术；给出的示例是 MySQL 和 SQLite。 | [E001] |
| C-002 | 服务依赖于已配置的 PlugIt Proxy API URL。 | [E002] |
| C-003 | 私有设置应位于单独的本地配置文件中，且不得发布到源代码控制。 | [E002] |
| C-004 | README 将协议和实现描述为草案，因此采用者应认为其成熟度有限。 | [E004] |

## 8. 验证与验收

| Requirement ID | Verification method | Acceptance criterion |
|---|---|---|
| FR-001 | 检查 | 配置文件包含文档化的设置，并且可证明服务使用这些设置进行环境配置。 |
| FR-002 | 演示 | 模型变更会生成 Alembic 升级文件，并且数据库可使用该文件进行升级。 |
| FR-003 | 演示 | 某个集成场景展示多个服务通过单一体验呈现，同时保留服务隔离。 |
| FR-004 | 演示 | 提供端点 URL 会产生一个已初始化的 API 访问实例。 |
| FR-005 | 测试 | 一封包含文本内容的有效入站电子邮件会触发 `newMail(data, payload)` 调用，且成功处理后会删除该消息。 |
| FR-006 | 测试 | 具有无效哈希或自动回复指示的消息不会被传递给邮件处理器。 |
| NFR-001 | 检查 | 特定环境的值定义在配置文件中，而不是硬编码在服务逻辑中。 |
| NFR-002 | 检查 | 模式版本变更由 Alembic 升级文件表示。 |
| NFR-003 | 检查 | 私有设置放置于排除在源代码控制之外的本地配置文件中。 |
| NFR-004 | 测试 | 自动生成的回复和无效哈希消息在邮件处理过程中被拒绝。 |
