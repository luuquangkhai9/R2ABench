# 软件需求规格说明书

## 1. 引言

### 目的
本 SRS 基于提交 `7a8099ad352668fce4f0dfc7ebd0354b29b7f301` 时仓库中的证据，仅规定 `Kangrand` 的外部可观察需求；`Kangrand` 是一个面向 `SECP256K1` 的命令行 Pollard's kangaroo 区间 ECDLP 求解器。

### 产品范围
该产品使用带 distinguished points 的 Pollard's kangaroo 求解 `SECP256K1` 上的区间离散对数问题，支持通过已保存的工作文件进行可恢复执行，并支持简单的服务器/客户端分布式执行模式。源支持仅限于仓库 README 证据。

### 目标读者
本文档面向运行求解器的操作员、使用其文件或网络接口的集成人员，以及根据仓库证据验证支持行为的审查人员。

## 2. 总体描述

### 产品视角
`Kangrand` 是一个独立的命令行区间 ECDLP 求解器，适用于 `SECP256K1`。它使用 distinguished point 方法存储选定的游走点并检测碰撞。它还支持保存、恢复、检查和合并工作文件，以及简单的分布式服务器/客户端模式。(`E001`, `E002`, `E004`, `E005`, `E006`)

### 产品功能摘要
- 接受一个包含十六进制值以及压缩或非压缩形式公钥的输入 ASCII 文件。(`E004`, `E005`)
- 使用带 tame 和 wild 群组的 Pollard's kangaroo 求解 `SECP256K1` 上的区间 ECDLP。(`E002`, `E004`)
- 定期保存工作，并从已保存的工作文件恢复。(`E001`, `E003`, `E006`)
- 检查工作文件信息并离线合并工作文件，包括合并后可求得密钥的情况。(`E001`, `E006`)
- 支持 `wsplit` 风格的备份，在每次备份后重置内存中的哈希表。(`E001`, `E006`)
- 支持简单的服务器/客户端分布式模式，包括使用备份间隔、distinguished bits 和配置文件启动的服务器，以及连接到指定服务器的客户端。(`E002`)

### 用户类别
- 本地操作员：通过命令行配合输入文件和工作文件选项运行求解器。(`E003`, `E004`)
- 分布式操作员：运行简单服务器和一个或多个客户端。(`E002`)
- 离线分析人员：检查并合并已保存的工作文件。(`E001`, `E006`)

### 运行环境
- 命令行执行环境。(`E002`, `E003`, `E004`)
- 基于文件的操作，使用 ASCII 输入和工作文件。(`E001`, `E003`, `E004`, `E005`, `E006`)
- 可选的联网服务器/客户端环境。(`E002`)
- 使用说明文本中提及可选的 GPU 支持客户端执行。(`E002`)

### 假设与依赖
- 该求解器专用于 `SECP256K1`。(`E004`, `E005`)
- 分布式部署依赖于操作员管理的网络，因为服务器没有认证机制。(`E002`)
- 在硬件变更或 distinguished-point 设置变更后继续工作文件是受支持的，但性能可能不是最优。这是根据 README 指导推断得出的。(`E003`, evidence type: inferred)

## 3. 外部接口需求

### 用户接口
产品应提供命令行接口，包含用于输入文件、工作文件保存/恢复行为、distinguished-point 大小以及分布式服务器/客户端操作的选项。(`E002`, `E003`, `E004`)

### 软件/API 接口
没有证据表明存在程序化 API。支持的接口为：
- 用于问题定义的 ASCII 输入文件。(`E004`, `E005`)
- 用于持久化、检查和合并工作流的工作文件。(`E001`, `E003`, `E006`)
- 启动服务器时使用的配置文件。(`E002`)

### 通信接口
产品支持一种简单的客户端/服务器通信模型，其中客户端连接到服务器。服务器没有认证机制。(`E002`)

### 数据交换格式
- 输入 ASCII 文件：十六进制值；公钥可以是压缩或非压缩形式。(`E004`, `E005`)
- 工作文件：证据中未指定其二进制或结构化文件格式，用于保存/恢复/信息/合并工作流。(`E001`, `E003`, `E006`)
- 服务器配置文件：证据中未指定格式。(`E002`)
