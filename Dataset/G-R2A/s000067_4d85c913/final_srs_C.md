# 软件需求规格说明书

## 1. 引言

### 目的
本 SRS 定义了针对提交 `890e67e2fc1ea0dcbdcb5164b665d6be245e5464` 的 TraceLeft 的、基于证据支撑的需求。范围涵盖 TraceLeft 库及其参考 CLI，该 CLI 通过 eBPF 和基于 Kprobe 的插桩来跟踪 Linux 进程。来源仅限于仓库证据包。

### 产品范围
TraceLeft 是一个库和一个小型 CLI 工具，它通过在函数调用上安装 Linux eBPF 探针来跟踪应用程序，从而接收来自被跟踪进程的系统调用、文件和网络事件的回调。它被定位为一个用于配置驱动的系统审计和应用跟踪的框架，包括网络和系统调用监控。[E002][E006]

### 目标读者
本文档面向：

- 使用 CLI 参考实现的操作人员。
- 验证外部可观察行为和接口的维护人员。

## 2. 总体描述

### 产品视角
TraceLeft 是一个由以下部分组成的 Linux 跟踪框架：
- 一个在 Linux 函数调用上安装基于 eBPF 和 Kprobe/Kretprobe 的探针的库。[E002][E006]
- 一个执行命令处理器的 CLI 入口点，其中包括一个用于跟踪进程的 `trace` 命令。[E003][E004]
- 一种探针/处理器模型，其中跟踪探针 tail-call 处理器探针，处理器通过共享事件映射发出事件，并使用公共事件区段进行分发。[E001]

### 产品功能摘要
TraceLeft 提供以下受支持的功能：
- 通过 CLI 命令跟踪 Linux 进程。[E004]
- 在 Linux API 和内部函数上安装探针。[E002][E006]
- 接收被跟踪进程的系统调用、文件和网络事件的回调。[E002][E006]
- 支持配置驱动的跟踪/审计用例。[E002][E006]
- 加载默认处理器探针和进程特定的处理器探针。[E001]
- 发出带有公共头部区段的事件，以便跟踪器能够分发它们。[E001]

### 用户类别
- 调用 TraceLeft 来跟踪进程的 CLI 操作人员。[E004]
- 使用该库/框架来构建系统审计或应用跟踪工具的开发人员/集成人员。[E002][E006]

### 运行环境
- Linux 系统。[E002][E006]
- 具有对 Kprobes 和 Kretprobes 的 eBPF 支持的内核版本。[E002][E006]

### 假设和依赖
- TraceLeft 依赖目标内核中对 Linux eBPF、Kprobes 和 Kretprobes 的支持。[E002][E006]
- 该实现使用 `gobpf` 构建。[E002][E006]
- 处理器探针应遵循探针加载器用于处理器映射更新的命名方案。[E001]

## 3. 外部接口需求

### 用户接口
- 应通过可执行入口点提供命令行接口。[E003]
- CLI 应提供一个 `trace` 命令，其用途是跟踪进程。[E004]

### 软件/API 接口
- 该库应与 Linux eBPF 和 Kprobe/Kretprobe 设施交互，以在函数调用上安装探针。[E002][E006]
- 探针子系统应加载默认处理器探针和进程特定的处理器探针。[E001]
- 处理器探针应通过跟踪器使用的共享事件映射发出事件。[E001]

### 通信接口
- 通过处理器用于向跟踪器发送事件的共享事件映射，支持从内核到用户空间的事件传递。[E001]

### 数据交换格式
- 事件数据应以用于事件分发的公共区段开始。[E001]
- 配置数据包括在生成的 protobuf 支撑结构中的事件参数元数据字段 `position`、`type`、`name`、`suffix` 和 `hash_func`。[E005]
