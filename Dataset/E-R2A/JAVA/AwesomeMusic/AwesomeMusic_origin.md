# 1 引言
## 1.1 目的

本需求规格说明书旨在对“AI音乐创作与分享平台”的接口需求、功能需求、性能需求、设计约束与软件属性等进行概括性说明，以便客户及产品经理确认产品的具体需求，以及便于开发人员根据需求设计编码。

本需求规格说明书的预期读者包括客户、产品经理、开发以及测试人员以及跟该项目相关的其他人员。

## 1.2 范围

本软件的名称是AI音乐创作与分享平台，其主体是一个为用户提供AI服务的Web系统。该系统根据用户输入的源文件来自动生成音乐作品并分享。凡热爱音乐并在本系统成功注册的用户均可使用该系统进行音乐创作与分享。

# 2 总体描述

## 2.1 产品描述

近年来，随着AI技术的快速发展，结合了AI技术的学习、娱乐产品如雨后春笋般诞生。AI音乐创作就是其中之一。本项目旨在制作一款在线AI音乐创作与分享平台，用户可以在该平台通过AI技术“创作”音乐并分享。  

本项目主体为Web系统，包含Web前端、Web后端、算法服务三个模块。

前端模块：为用户提供可交互的Web界面，用户通过前端实现登录、源文件上传、音乐生成、音乐分享等功能。  

后端模块：为Web前端提供数据接口，并提供数据存储、服务协调调度等功能。  

算法服务：模块用来根据用户输入的源文件生成音乐，其为后端提供算法服务。算法模块包含在线的音乐生成服务与离线的模型迭代升级服务。

## 2.4 用户特点

本项目的用户只有一类，即享受产品服务的用户。产品面向的主体用户是音乐爱好者，该类用户对手机和电脑等产品依赖更深，更加容易获得互联网的产品服务，也更有兴趣追求新奇的音乐创作方式。而且如今音乐的获得变得更加容易，用户对音乐的品鉴水平也逐步提升，追求也更加苛刻，该类用户对产品需求的特点大致可以分为三类：广、快、精。  

所谓“广”是指生成音乐的广度，即能够训练的音乐的种类数目要足够多，能满足用户的各种音乐品味。在用户量足够多的情况下，用户很有可能对当下任一曲风感兴趣。因此，产品的训练模型需要能生成当下热门曲风的曲谱以及相对冷门曲风的曲谱。  

所谓“快”既是指用户对产品在用户进行上传、下载和浏览网页等情况下的响应时间的要求，也是对模型训练曲谱时间的要求，尽量避免用户过度等待。同时，产品也能根据用户的喜好特点及时更新曲谱推荐，根据用户或曲谱的受欢迎程度更新用户热榜和曲谱热榜。 

所谓“精”是主要是指用户对音乐质量的要求。生成音乐的质量应在水准线以上，并且当前热门音乐能满足一般用户对生成音乐产品成色的要求。此外，产品的界面也要满足用户对界面友好性的需求，操作流程因尽量避免复杂、无意义的操作。

## 2.6 假设和依赖关系

### 2.6.1 假设关系

在本次软件产品需求分析中，需要考虑影响需求和后续计划的假设因素。如果这些假设因素被修改，就会使软件产品开发项目受到影响。这些假设的因素可能包括：

+ 计划使用的编程语言和开发框架修改，可能会导致项目的部分计划阶段无法按时完成，甚至会影响到项目的整体完工周期；
+ 计划使用的服务器等临时硬件设备无法得到满足，则会影响到产品的部署规划；
+ 计划的需求分析用后期被修改，导致重新进行需求分析，修改文档，修改代码，有可能带来较大困难，延迟完成工期；
+ 计划的产品研发组人员有所变动，导致预计工期延长或缩短；
+ 研发组成员之间沟通出现偏差，反馈不及时，导致项目最终合并时出现问题，给产品质量和开发工期带来风险；
+ 计划使用的算法模型难以满足用户需求，可能会导致最终产品质量的下滑，无法满足用户需求。
### 2.6.2 依赖关系  

产品主要分为前端、后端和算法三个模块，因而模块之间的依赖关系主要从这三个方面和时间之间的关系考虑：  
+ 在需求分析阶段，应对各个模块的需求全面分析，用户对产品的全部需求均需要记录在案，避免后期更改该需求或者产品功能无法得到用户满意；
+ 在产品设计阶段，以图的形式展现对用户需求的满足的设计，在设计阶段应与后期的开发相联系，比如在类图中变量应与开发中使用的类变量名称尽量统一；
+ 在产品开发阶段，各个模块之间依赖性不强，因而只需处理好各个模块与时间的依赖关系，根据项目计划抓紧完成进度；
+ 在产品测试阶段，各个模块之间的稳定协作需要得到保证，保证系统的稳定运行，如期保质完成系统测试。

### 3.2.2 算法模块

<div align='center'><img src='assets/use-case-algo.svg'/></div>
<div align='center'>图 3.8 算法模块用例图</div>
<br>

如图所示算法模块的用例分为：训练生成模型、生成曲谱、分类所有曲谱和推荐歌曲四个部分。整体的思路是训练生成模型和生成曲谱使用 GPT-2 模型，每个用户有且仅有一个属于自己的 GPT-2 曲谱生成模型，这个模型将会每日更新。分类所有曲谱和推荐歌曲使用 LSTM 模型，该模型在整个系统中只有一个，在进行用户推荐时，将使用 LSTM 学得的表征计算音乐的余弦相似度。

### 3.3.2 交互需求

本系统主要面向没有音乐制作经验或音乐制作初学者学习使用，所以系统交互需要尽可能简单易懂，不需要专业的功能设计。系统应当具备全面的用户使用说明、提示及引导，方便没有类似系统使用经验或音乐制作经验的用户快速上手使用。

### 3.3.3 安全性

网络安全性：本系统网关需要严格隔离系统网络的内外边界，以避免安全配置较宽松的内部系统在系统外部暴露。

数据安全性：系统中重要数据需要3副本存储，以避免某一存储介质损坏时数据丢失。

### 3.3.4 健壮性

本系统需要保证一定的系统可用性，在系统内部分节点升级、宕机或一定程度的网络分区发生时能够正常继续使用。
