﻿# Campus Helper Platform Software Requirements Specification (Standard SRS Extract)

## 1. Introduction

### Purpose
Its purpose is to provide structured input for architecture generation, test design, and requirements traceability for the Campus Helper platform.

### Product Scope

The Campus Helper platform is a campus trading platform based on a WeChat Mini Program. It serves campus takeout/express pickup, immediate takeout transfer, and second-hand information publishing. Through a publish-and-accept-order model, the platform supports information flow for errand products and second-hand product transactions and aims to provide a more standardized and reliable way to obtain transaction information.

This document uses the specification definitions of platform, product, errand product, second-hand product, user, guest, seller, customer, order, errand order, second-hand order, tag, administrator, log, order status, publish product, search product, and QPS.

### Intended Audience

This document is intended for platform users, software developers, requirements analysts, testers, architecture generation workflows, and requirements review workflows. Target end users include students, teachers, and family members; management users are platform administrators.

## 2. Overall Description

### Product Perspective

The system is a WeChat Mini Program trading platform. The specification designs it as a four-layer architecture: presentation layer, business layer, data layer, and data entity layer (database). Overall, the system is divided into six functional categories: product information viewing, order module, personal center, product management, order management, and user management. The specification does not provide server deployment topology, API protocol, or database table structure.

### Product Functions Summary

| Capability | Summary |
| --- | --- |
| Product browsing | Users or guests can view popular products, browse products by category, and enter detail pages; registered users can further favorite or place orders. |
| User orders | Logged-in users can create orders, modify order remarks, confirm orders, and cancel orders. |
| Personal center | Logged-in users can view favorites and their own order records. |
| Administrator product management | Administrators can view overall platform product status, view product details, search products, modify products, and delete products. |
| Administrator order management | Administrators can view all orders, view a single order, and modify order details. |
| Administrator user management | Administrators can view all users, view a single user, and modify user information. |

### User Classes

| User Class | Responsibilities / Needs |
| --- | --- |
| Guest | Has no platform account and can view products, but core functions such as favorites and ordering are restricted. |
| Registered user | Has a platform account and can browse, publish, and favorite products, and participate in transactions as customer or seller. |
| Customer | Browses products and places orders for desired products. |
| Seller | Publishes errand products or second-hand products and acts as the product publisher in transactions. |
| Administrator | Supervises violations, manages violating product information, and views and modifies product, order, and user information. |
